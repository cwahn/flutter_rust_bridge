# ActorRef Delegate Implementation Investigation

## Problem Identified
The current ActorRef implementation has several inconsistencies and missing pieces that indicate I was implementing it incorrectly.

## Key Issues Found

### 1. CST Encoder Inconsistency
**Current Implementation**: 
```rust
MirTypeDelegate::ActorRef(_) => Acc::distribute(Some(
    "return cst_encode_String(raw.id.toBytes());".to_string(),
)),
```

**Issue**: This bypasses the proper delegate pattern by directly calling `cst_encode_String()`. Other delegate types like UUID follow the pattern:
```rust
MirTypeDelegate::Uuid => Acc::distribute(Some(format!(
    "return cst_encode_{}(raw.toBytes());",
    uint8list_safe_ident(true)
))),
```

### 2. Missing Dart-Side ActorRef Class
**Evidence**: No ActorRef Dart class exists in the FRB codebase, but UUID has `UuidValue` class.

**UUID Pattern**:
- Dart class: `UuidValue` with `.toBytes()` and `.fromByteList()` methods
- Generated codec functions: `sse_encode_Uuid()`, `sse_decode_Uuid()`, `dco_decode_Uuid()`

**ActorRef Gap**: No corresponding `ActorRef` Dart class or methods like `.toBytes()`, `fromId()`, etc.

### 3. Missing Codec Function Generation
**UUID Pattern** (from examples):
- `sse_encode_Uuid(UuidValue self, SseSerializer serializer)` 
- `sse_decode_Uuid(SseDeserializer deserializer) -> UuidValue`
- `dco_decode_Uuid(dynamic raw) -> UuidValue`

**ActorRef Missing**: No corresponding codec functions are being generated.

## Comparison: UUID vs ActorRef Implementation

### UUID (Working Pattern)
1. **Delegate Type**: ✅ `MirTypeDelegate::Uuid`
2. **Dart Class**: ✅ `UuidValue` class with `.toBytes()` and `.fromByteList()`
3. **CST Encoder**: ✅ `return cst_encode_{}(raw.toBytes())`
4. **SSE Codec**: ✅ Auto-generated `sse_encode_Uuid()` and `sse_decode_Uuid()`
5. **DCO Codec**: ✅ Auto-generated `dco_decode_Uuid()`
6. **Wire Protocol**: ✅ Serializes as `list_prim_u_8_strict` (byte array)

### ActorRef (Current Issues)
1. **Delegate Type**: ✅ `MirTypeDelegate::ActorRef` 
2. **Dart Class**: ❌ No `ActorRef` Dart class
3. **CST Encoder**: ❌ Bypasses delegate pattern with direct String encoding
4. **SSE Codec**: ❌ Missing proper codec generation
5. **DCO Codec**: ❌ Missing proper codec generation  
6. **Wire Protocol**: ❌ Inconsistent - some places use String, others use bytes

## Root Cause Analysis

### Problem 1: Architecture Confusion
The implementation mixes two different FRB patterns:
- **Delegate Pattern**: For types with custom serialization (UUID, Vec, StreamSink)
- **Opaque Pattern**: For types that are opaque to Dart with method generation

The `actor_ref_methods.rs` file suggests opaque pattern, but the delegate implementation suggests delegate pattern.

### Problem 2: Missing Dart Infrastructure
Unlike UUID which has a complete Dart ecosystem:
- `UuidValue` class
- `.toBytes()` and `.fromByteList()` methods  
- Full codec integration

ActorRef has none of this Dart-side infrastructure.

### Problem 3: Codec Generation Gap
The SSE/DCO codec functions are generated by:
- `generate_encode_or_decode_for_type()` in `codec/sse/body.rs`
- `CodecSseTyTrait::generate_encode/decode()` methods

These aren't being properly triggered for ActorRef.
